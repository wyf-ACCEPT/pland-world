Agentic Payment
真正改变了什么

当软件开始自主选择供应商、调用 API、购买服务，它不只是“帮人付款”——它开始持续地产生财务后果。

核心问题不是给 Agent 一张卡，而是让它在 可证明的授权 内花钱，并把错误半径锁在公司承受得起的范围。
旧系统的对象

一笔 transaction：能不能扣款。

新系统的对象

一个 mandate：为什么能花、最多花多少。

产品机会

授权、预算、执行、凭证与恢复的控制层。

01 · The structural problem

一个 Facebook 广告案例，就能看懂旧支付栈为什么不够

广告是连续发生的经济活动，但卡支付通常不是连续结算。两者之间的时间差，就是信用风险。

STEP 01

广告先交付

Meta 已经提供曝光或点击，广告主先获得了服务。

STEP 02

累计后扣款

消费达到 payment threshold 或账单日，Meta 才向卡发起扣款。

STEP 03

卡可能失败

余额不足、虚拟卡失效或账户被抛弃，已交付服务变成应收款；追不回才形成坏账。

每次消费立即刷卡

信用敞口小，但极小额交易的固定处理成本可能吃掉收入。

攒到较大金额再刷

处理成本下降，但服务商必须先给信用，承担扣款失败风险。

我们的语义判断：这个案例不是为了证明“必须用稳定币”，而是在证明——当经济活动变成机器速度，支付、信用控制和服务交付必须进入同一个实时工作流。
02 · What the forum converged on

三场会议，其实都在回答同一个问题

怎样让 Agent 获得足够的自主权，又不获得无限的财务权限？

14:13 · RISK

签名不等于正确

托管、盲签、KYT 和冻结说明：钱能移动，不代表交易安全、合规或可恢复。

14:30 · ECONOMICS

支付频率不等于结算频率

逐请求计量可以实时；外部资金可以按余额、阈值或账期聚合结算。

14:57 · PRODUCT

稀缺的是授权凭证

企业真正需要的是把用户授权安全地扩展给 Agent、应用和协议，并处理错误责任。

03 · The control loop

Agentic Payment 是一个控制闭环，不是一根付款管道

Agent 可以提出行动，但金融执行必须由确定性的权限、政策和账务系统约束。

Before payment

花钱之前

  • 谁代表谁行动
  • 任务、用途和供应商
  • 额度、频率、期限与审批
  • 风险与合规检查
During payment

花钱之中

  • 计量用量与实时预算
  • 预留资金或控制信用敞口
  • 选择卡、银行、余额等轨道
  • 幂等、重试和异常暂停
After payment

花钱之后

  • 证明服务是否交付
  • 把请求、账务和结算对上
  • 退款、争议与人工接管
  • 重建完整决策证据
The new primitive

Agent 需要的不是无限钱包，而是一张可撤销、可解释的 Spending Mandate。

04 · Product thesis

公司的切入点：Agent Spend Control Layer

先回答“为什么可以花”，
再处理“出错后谁负责”。

产品不是替 Agent 再接一个支付 API，而是在 Agent 与任何支付轨道之间加入统一的委托、预算、账本和证据层。

委托

主体、任务、范围、额度、期限与撤销。

控制

政策、风险、审批升级和异常停止。

账务

逐请求计量、资金预留与聚合结算。

证据

交付、对账、退款和争议材料。

轨道是实现选择，不是产品定义。 卡、银行、预付余额或稳定币都可以接入；稳定币可能改善某些预付和跨境结算，但不替代授权与责任。
FIRST WEDGE

企业 API / 模型 / 数据 / 工具消费

这是最接近 Agent 原生工作的支出：频率高、可计量、供应商明确、预算可限制，也能直接观察信用敞口和对账成本。

每月预算 50,000 · 白名单供应商 · 每请求记账 · 达阈值聚合结算 · 越界转人工审批
NOT YET

开放式 C 端代购

错误购买、受理、退款、拒付和消费者保护过于复杂，不适合作为第一个验证场景。

05 · 90-day test

90 天只验证一件事：企业会不会为“安全自主”付费

不要先造通用协议或新链。用真实请求与真实资金流，验证控制层是否降低审批、信用和对账成本。

WEEK 1–2

找到真实支出流

选择一个多模型/API 企业客户，画清审批、扣款、信用与月结流程。

WEEK 3–8

搭最小控制闭环

实现 mandate、政策、计量账本、资金预留、凭证与异常接管。

WEEK 9–13

受控生产试点

白名单、低额度、短授权；对比现有卡/余额方案的真实结果。

安全自动完成率最大信用敞口每个经济事件成本异常 / 重复率对账工时客户愿付价格
