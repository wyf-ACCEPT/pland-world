数据买方品类地图

谁在公开买 agent 数据、买什么品类、按什么指标验收、出什么价。只收公开且能落地的采购证据——「技术方向对得上」「正在大规模招人」「理论上肯定需要数据」这类一律不算数。按这个门槛筛完，结果和直觉差得很远。

一句话结论

公开挂着实时需求、能直接对接的直接数据买方只有两家：Labelbox Prism 和 Mercor Data。Turing、Surge AI、Mercor 专项和 Handshake 买的是按题目生产的环境与专家产能，不是现成的数据包。

⚠️ 而 OpenAI、Anthropic、Cursor、Kimi、Qwen、Poolside —— 一家都没有公开的采购入口。

分类口径

「买方」是怎么定义的

这套分类的价值在于它能被证伪。一家公司在招 AI 训练相关的岗位、或者技术路线上显然需要数据，都不足以说明它在买数据。要进这张地图，必须有公开、能落地的证据。

类别进表门槛对卖方意味着什么
直接买现成数据
挂着实时需求		 公开列出正在收的数据类型、经济条款，并有投递入口 可直接卖存量资产 手上已有的数据可以直接报过去
直接买现成数据
需先谈合作		 公开数据范围、抽取与匿名化流程、付款节点 可以谈区域供给或数据处理合作，但要先确认字段规格与价格
不买现成的
按题目委托生产		 公开付费题目、交付物、贡献者要求，以及价格或验收标准 卖的是团队和产能，不是数据包。攒好的日志在这里没有对应的收购口
相邻的授权市场 权利、质检、许可、分成机制清晰，但数据品类不是 agent trace 只用来学机制，不计入买方数量

⚠️ 读这条的时候要注意

谁不在这张地图上

下面这些公司长期看多半是终端客户，但按前面的门槛，现在都没有足够公开、可落地的采购规格，因此不进主表。

公司为什么不进表什么情况下重新纳入
OpenAI有一般性的 Data Partnerships，但没有针对 agent trace 的实时品类、统一 schema、价格或验收指标出现 agent / workflow 的公开招标、供应商准入或明确题目
Anthropic公开在建 RL、Computer Use、Evals，但无公开采购题目或供应商准入要求出现 environment / trace 的公开采购入口
Cursor自己就握着极强的一方 coding 数据闭环；无公开外购规格发布外部数据 / benchmark 采购需求
Kimi / Qwen / Seed技术方向显示存在潜在需求，但无公开外采要求、价格和投递入口出现采购联系人、招标、付费项目或供应商准入
Poolside公开披露过曾从外部供应商战略性收购数据，但没有当前的采购需求、schema 或入口出现新的外部数据需求或收购入口
Scale / Mechanize / Invisible 等主要身份是向模型公司卖数据和环境的供应商，更接近同行或渠道，不是买方公开采购区域供给、垂直产能或分包
⚠️ 这条要小心引用

「没有公开采购入口」不等于「不买数据」。它们几乎肯定在买，只是不在台面上买——走的是私下的供应商关系和保密合同。

所以这张地图真正说明的是：公开渠道能触达的买方，和实际花钱最多的买方，不是同一批人。想接触后者，公开调研到此为止，只能靠人脉。

机制

市场到底在为什么付钱

把四家委托生产方的做法叠在一起，会看到同一条链——个人产生的 agent 轨迹确实已经被付费了，但产品形态不是开放上传市场。

01
买方出题
先定义要什么能力、什么验收标准
02
受控执行
贡献者在指定环境里真的做一遍
03
同步录制
录屏 + 工具调用轨迹
04
结果
成功还是失败，有明确判据
05
人工解释
书面说明 + 评分标准打分
06
授权证据
逐任务同意书，权利链可查
推论

⚠️ 这条链意味着：「先攒一堆历史日志、再脱敏、再转卖」这条路，市场已经用「按题目生产」绕过去了。

因为从源头就是买方定义的、贡献者知情同意的、权利干净的数据，根本不需要事后补一层脱敏去追回权利。存量日志要挤进这条链，缺的不只是字段，还有从一开始就该在场的同意书。
